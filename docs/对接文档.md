## 〇、给接手的 AI：先读这一节

### 0.1 项目是什么

仿 `vocabili.top`（术力口数据库）的 **B 站虚拟歌姬中文曲排行榜站**。

- 数据源：B 站 **30 号分区（VOCALOID·UTAU）** 的公开数据
- 周期：日 / 周 / 月 / 年四类，统一以周期起始日 **01:00** 为界
- 计分：官方评分公式（播放/互动/收藏/硬币/点赞得点 + 修正 A/B/C/D），**看增量不看累计**
- 参考站点：`vocabili.top`（界面基准）、`evocalrank.com`（周增量兜底数据源）

## 一、布局对接：侧边栏按路由条件显示

### 1.1 参考站行为

- **带侧边栏的页面**（可通过左侧"快捷导航"进入）：左侧显示 `aside` 侧边栏 + 右侧内容；
- **不带侧边栏的页面**（视频详情、歌手详情、用户详情等）：无 `aside`，内容居中铺满。

### 1.2 侧边栏路由判定（前端唯一数据源）

文件：`apps/web/src/components/MobileNav.jsx`

```js
export const SIDEBAR_PREFIXES = [
  "/", "/rank", "/rank-block", "/search", "/singers",
  "/calculator", "/stats", "/achievements", "/today",
  "/interaction", "/ai", "/about", "/random", "/tags",
];

export function isSidebarRoute(pathname) {
  if (pathname === "/") return true;
  return SIDEBAR_PREFIXES.some(
    (p) => p !== "/" && (pathname === p || pathname.startsWith(`${p}/`)),
  );
}
```

判定规则：
- `/` → 带侧边栏；
- `pathname === prefix` 或以 `prefix + "/"` 开头 → 带侧边栏；
- 其余路径（如 `/video/:aid`、`/singer/:id`、`/member/:mid`、`/auth/success`）→ 不带侧边栏。

> 注意：`/singers`（歌手列表，含侧边栏）与 `/singer/:id`（歌手详情，不含侧边栏）是不同前缀。
>
> 注意：参考站**仅首页与榜单页**带 `<aside>`，本站 `SIDEBAR_PREFIXES` 覆盖更宽，
> 这是**按用户明确指定的规则**实现的，不要擅自按参考站收窄。

### 1.3 布局实现

文件：`apps/web/src/App.jsx`

- `const withSidebar = isSidebarRoute(location.pathname);`
- 路由表统一由 `AppRoutes` 组件承载，两种布局复用同一份 `<Routes>`。
- 带侧边栏分支（与参考站 `01-home.html` 一致）：

```jsx
<div className="mx-auto flex max-w-7xl gap-0 px-2 pb-10 pt-4 xs:px-3 md:px-4 md:pb-16 md:pt-4 xl:gap-6 xl:pt-6">
  <aside className="hidden w-44 shrink-0 xl:block">
    <div className="sticky top-4"><SideNav /></div>
  </aside>
  <main className="min-w-0 flex-1 space-y-4 md:space-y-6">
    <AppRoutes />
  </main>
</div>
```

- 不带侧边栏分支（详情页居中）：

```jsx
<main className="mx-auto w-full max-w-7xl space-y-4 px-2 pb-10 pt-4 xs:px-3 md:space-y-6 md:px-4 md:pb-16 md:pt-4 xl:pt-6">
  <AppRoutes />
</main>
```

- 侧边栏在 `< xl`（1280px）断点下隐藏（`hidden xl:block`），与参考站一致。
- 本页 `RankPage` 根节点**不可再写 `<main>`**（App 布局已提供），否则造成 `<main>` 嵌套。

## 四、榜单增量口径（对接定义）

### 4.1 周期窗口

四类周期统一以**周期起始日 01:00** 为边界，实现在 `apps/api/src/services/index.js` → `windowOf()`：

| 周期 | 窗口 |
|---|---|
| 日榜 | 今日 01:00 ～ 明日 01:00 |
| 周榜 | 本周一 01:00 ～ 下周一 01:00 |
| 月榜 | 本月 1 日 01:00 ～ 下月 1 日 01:00 |
| 年榜 | 今年 1 月 1 日 01:00 ～ 次年 1 月 1 日 01:00 |

### 4.2 增量基线（重要）

增量 = 当前值 − **窗口起始日前一天**的快照值。

```js
// services/index.js
function baseDayKey(win) {
  return dayKeyOf(win.startTs - 86400);
}
```

- 快照按自然日归档于 `cache/stat_daily/YYYY-MM-DD.json`，而周期起点是 01:00，
  所以基线日必须写 `startTs - 86400`，**不能**写 `startTs - 1`
  （后者仍落在起始日当天，而当天快照会被当日采集反复覆盖，导致增量恒为 0）。
- 四类周期统一成立：日=昨天、周=上周日、月=上月末、年=上一年 12-31。
- 快照缺失时回退 evocalrank 周增量累加（`evoStats.sumWindow`），任意周期均适用。

### 4.3 新歌 vs 老歌

- **新歌**（`pubdate` 落在本窗口内）：无基线，用**当前累计值**计分；
- **老歌**：用上述增量计分。

### 4.4 历史回溯（上期排名 / 历史最高 / 成就）

`scoreWindow()` 用 `statHistory.deltaSnapshot(期初快照, 期末快照)` 还原历史某一期的分数，
口径与当期 `buildBoard()` 一致：

- 期初快照日 = `baseDayKey(win)`；期末快照日 = `dayKeyOf(win.endTs - 1)`；
- 首尾快照缺任一 → 返回 `null`，该期**跳过**（不当作「未上榜」）；
- 窗口内新歌无期初基线 → 用期末累计值；无基线且非新歌 → 该期无法还原，跳过。

据此派生的字段：`prev_rank` / `prev_score` / `delta`（相对上期分数增幅）/ `streak`（连续在榜期数）/
`peak_rank`（历史最高名次，仅优于当前时给出）/ `achievements`（见 4.5）。

### 4.5 永久成就

| 成就 | 条件 | 实现 |
|---|---|---|
| SUPERHIT | 累计 2 次登上主榜前 3 | `top3Count >= 2` |
| 门番达成 | 28 期内 20 次 **或** 50 期内 30 次登上主榜（前 20），且无连续 8 期未上榜 | `(on28 >= 20 \|\| on50 >= 30) && no8Miss` |
| 神话达成 | 播放总量突破一千万 | `view >= 10_000_000` |
| 年榜首位 | 首次成为年榜首位 | `period === "annual" && score_rank === 1` |

回溯上限 `LOOKBACK_MAX = 50` 期；主榜定义为前 `MAIN_TOP = 20` 名。

### 4.6 数据依赖

历史回溯依赖 `cache/stat_daily/` 的每日快照密度。当前快照存在断档

### 5.2 基准快照的三条须知

1. **有 7 份快照是误抓，不可作基准**：`19-vocalists`、`20-producers`、`21-synthesizers`、
   `22-uploaders`、`23-statistics`、`24-on-this-day`、`25-ed-history` 均约 96.9 KB 且含首页特征文案
   （最新排行 + 成就速递 + 数据总榜），实际抓到的是首页。统计页可靠基准只有 `51-stats-auth.html`。
2. **注意登录态**：同一页面可能有未登录 / 已登录两份，内容不同。
   例：歌曲详情页「达成里程碑」只出现在 `58-song-auth.html`，`06-song-detail.html`（未登录）没有。
3. **审计必须带参数**：空态页面会漏掉关键结构造成误报。
   例：搜索页不带 `keyword` 时处于「历史/热搜」空态，分类栏与结果网格都不渲染，会被误判为「缺失」。

### 5.3 Tailwind 动态类名陷阱

`text-${color}-500`、`bg-${c}-500/10` 这类模板串在**构建期扫描不到**，样式会静默丢失。
颜色类必须写成**静态映射表**，例如 `SingerDetailPage.jsx` 的 `SUM_TONE`。

| 位置 | 变体 |

### 5.6 外部图片与静态资源

**B 站图片 CDN 有防盗链**，实测 `i0/i1/i2.hdslb.com`：

| Referer | 结果 |
|---|---|
| 无 | 200 |
| `http://127.0.0.1:1005/` | **403** |
| `https://www.bilibili.com/` | 200 |

即「带非 B 站来源的 Referer 就拒绝」。现有三层防护，**新增图片时不要破坏它们**：

1. `apps/web/index.html` 的 `<meta name="referrer" content="no-referrer" />` —— 文档级策略，
   从首字节生效，覆盖 CSS 背景图与懒加载竞态；
2. 组件上的 `referrerPolicy="no-referrer"` —— 逐图声明，**新增外部 `<img>` 时务必带上**；
3. `apps/web/src/main.jsx` 的**捕获阶段** `error`/`load` 监听 —— 加载失败自动
   `visibility:hidden` 露出容器 `bg-muted` 占位，换 `src` 成功后恢复。
   （`img` 的 `error`/`load` 不冒泡，必须用捕获，否则监听不到。）

**站点图标**：`apps/web/public/favicon.svg`（原创，蓝→粉渐变 + 双八分音符）。
`index.html` 用 `<link rel="icon" type="image/svg+xml">` 引用，头部 logo 用的是同一个文件
（参考站头部 logo 为 `h-5 w-5 rounded-sm object-cover`）。要换 logo 直接替换这个文件即可。

> ⚠ **不要**直接把 `apps/web/public/` 整个删掉：头部 `<img src="/favicon.svg">` 会变成死链，
> 而 Vite 的 SPA fallback 会让它返回 200 的 HTML（不是 404），排查时容易被误导。
