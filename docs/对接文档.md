### 0.1 项目是什么

仿 `vocabili.top`（术力口数据库）的 **B 站虚拟歌姬中文曲排行榜站**。

- 数据源：B 站 **30 号分区（VOCALOID·UTAU）** 的公开数据
- 周期：日 / 周 / 月 / 年四类，统一以周期起始日 **01:00** 为界

- 参考站点：`vocabili.top`（界面基准）、`evocalrank.com`（周增量兜底数据源）

### 0.7 版本纪律（2026-10-03 起强制）

**为什么立这套规矩**：这个项目几乎全是 AI 改的，人基本不读 commit。结果是 commit 写得含混、
GitHub Contributors 图显示不出真正的作者、三个月后没人（包括 AI 自己）说得清动过什么。
**光有约定没用，必须做成机器拦得住的门禁。**

#### 一、身份

- 仓库级 `git config user.name/user.email` 已设为真实账号
  （`LingMowen <176232342+LingMowen@users.noreply.github.com>`，即 GitHub 的 noreply 邮箱）。
- 之前 19 个提交署名为假身份 `xngschina-dev <dev@xngschina.local>`，
  由仓库根目录 **`.mailmap`** 归一。**不重写历史**，只改「显示与归属」，GitHub 认这个文件。
- 校验是否生效：
  ```bash
  git log --use-mailmap --format="%aN <%aE" | sort -u     # 应只出现 LingMowen 一行
  ```
  ⚠️ **必须用大写 `%aN` / `%aE`**（套用 mailmap 后的值）。小写 `%an` / `%ae` 永远是提交里的
  原始身份，用小写去验证会误判成「没生效」——这个坑踩过一次。

#### 二、提交信息门禁（`commit-msg`）

- 模板：`.gitmessage`（已配 `git config commit.template`，`git commit` 会自动带上）。
- 首行必须是 `<type>(<scope>): <摘要>`，`type` ∈ feat/fix/docs/refactor/chore/test/perf/build/ci/style/revert，
  摘要 ≤72 字符。
- 正文**必须**有两行：`改动：…` 和 `验证：…`。这是最关键的约束——纯 AI 开发最容易丢的就是
  「改了什么」和「怎么确认没坏」，人没看懂，AI 也没留痕。
- ⚠️ **小节标题不能写成 `## 改动`**：git 会把以 `#` 开头的行当注释剥掉，
  写 `##` 等于什么都没写，提交会静默丢掉这两段。必须用不带 `#` 的「改动：」「验证：」。
- 临时绕过：`git commit --no-verify`（会留在 reflog 里）。

#### 三、推送门禁（`pre-push` → `scripts/preflight.js`）

推送前自动跑，BLOCK 项会拦住推送：

| 检查 | 级别 | 内容 |
|---|---|---|
| 禁入路径 | BLOCK | `old-files/`、`.env`、`.env.*`（`.example` 除外）、`docs/开发日志.md`、`.workbuddy*/`、`.reference/`、`参考文件/`、`SDK/`、`home-before.png` 是否被 git 跟踪 |
| 凭据扫描 | BLOCK | 从 `apps/api/.env` 抽出每一条**真实**凭据值（≥8 字符），逐条在跟踪文件里搜 |
| 通用密钥模式 | WARN | AWS AKIA / `gh[pousr]_` / `xox[baprs]-` / 私钥头 / JWT / `sk-…` |
| 语法 | BLOCK | 全部跟踪 JS 过 `node --check` |
| JSON | BLOCK | 全部跟踪 `.json` 能解析 |
| 未提交/未跟踪 | WARN | 列出但不拦 |
| 服务健康 | WARN | 1003 / 1005 是否活着 |

- 手动跑：`npm run preflight`（`--json` 出机器可读结果）。
- **验证门禁本身有效**：`npm run preflight:selftest`。它用合成假凭据走完整链路，
  断言「泄进跟踪文件 → exit 1 被拦」「撤掉 → exit 0 不误伤」「通用模式 → WARN」。
  一道从没被验证过会亮的警报等于没有，所以这个自测是纪律的一部分。
- 临时绕过：`SKIP_PREFLIGHT=1 git push`。

#### 五、装钩子（clone 之后必须做一次）

钩子源在 `scripts/git-hooks/`，通过 `git config core.hooksPath` 让 git 直接读那份被跟踪的源。
**不往 `.git/hooks/` 里拷** —— 拷过去的副本不在版本库里，clone 后必然失效，还会和源悄悄跑偏。

```bash
npm run hooks:install     # 装 / 刷新，并校验行尾是 LF
npm run hooks:check       # 只检查不修改
```

`.gitattributes` 已把 `scripts/git-hooks/*` 钉成 `eol=lf`。**钩子文件里只要有一个 CRLF，
Git for Windows 就会报 bad interpreter，钩子静默失效**——表现为「门禁莫名其妙没拦」。

##### ⚠️ 要对公网开隧道，必须用 `--preview`

**dev server 会把整个仓库当静态根。** 只要落在 vite `server.fs.allow` 范围内
（默认 = 仓库根），任何人访问 `/@fs/<绝对路径>` 就能原样拿到文件。实测（本机 1005）：

| 请求 | 结果 |
| --- | --- |
| `/@fs/E:/编程/xngschina/.git/config` | **200 / 2768 B 真实内容** |
| `/@fs/E:/编程/xngschina/apps/api/cache/library.json` | **200 / 26,363,205 B**（25 MB 全量数据） |
| `/@fs/E:/编程/xngschina/apps/api/.data/app.db` | 200 / 32768 B（SQLite 用户库） |
| `/@fs/E:/编程/xngschina/apps/api/.env` | 403（被 vite 默认 `fs.deny` 挡住） |

`.env` 挡住了是运气，其余全敞着。**dev server 本来就只该本机自己用。**

`preview` 只服务 `apps/web/dist/`，同样几条 `/@fs/` 路径全部返回 `index.html` 的
SPA 回退（1363 B / `text/html` / 不含仓库路径字样 / 与首页字节完全相同），泄露面关闭。
两个模式端口分开（dev 1005 / preview 1007），`start` 切模式时会先清掉另一模式的残留，
`stop` / `status` 覆盖全部，不会出现两个 web 抢同一个后端。

隧道一条命令（quick tunnel，免登录，但无 uptime 保证）：

```bash
cloudflared tunnel --url http://localhost:1007 --no-autoupdate
```

前端所有请求走相对路径 `/api/*`，由 preview 的代理转到 `http://localhost:1003`，
所以**隧道只需暴露 1007 一个端口**，API 与页面同源，没有 CORS 问题。

> vite 5.4.12+ 会校验 Host 头以防 DNS rebinding，隧道域名不加白名单会直接 403。
> `apps/web/vite.config.js` 里 `server.allowedHosts` 与 `preview.allowedHosts` 都已设为
> `[".trycloudflare.com"]`（**不要用 `true`**，那等于关掉整个防护）。

三条设计取舍，都踩过才知道：

- **不用 `node --watch`。** `--watch` 会 fork 子进程跑真正的服务，于是 pid 文件里的 pid
  和占着端口的 pid 永远不同，`status` 的漂移检查会一直误报——**误报多了人就不看警告了**；
  而且杀掉子进程后 `--watch` 父进程会把它重新拉起来，`stop` 之后端口又回来了。
  改代码就跑一次 `svc:restart`，比一个会骗人的自动重启可靠。
  （`npm run dev:api` 仍保留 `--watch`，那是并发前台调试用的，与托管模式互不干扰。）
- **stop 同时看 pid 文件和端口实况**，取并集。只信 pid 文件会漏掉「上次是别的方式起的」
  这类僵尸，只信端口则可能在服务正常时误杀别人的进程——这里取并集最稳。
- **start 前先看端口。** 端口被占就明确报出占用者并 exit 1，**不闷头起第二份**。
  下一轮 AI 最容易犯的错就是「端口被占 → 结论是别的项目在用 → 去改配置」。

> ⚠️ Windows 上 `spawn` 一个 `.cmd`（比如 `npm.cmd`）需要 `shell: true`，
> 所以脚本里**直接用 `process.execPath` 跑入口 JS**，不经过 npm —— 少一层进程，
> pid 也才是真的。

##### ⚠️ 开了隧道，就要收紧只给本机用的端点

隧道把 API 1003 一起暴露出去之后，**任何原本「反正只有本机能访问」的端点都变成公网可达**。
这三个端点前端一个都没用（`apps/web` 里 grep 零引用），只服务于本机进度页 1006，所以直接
按「本机直连」锁掉（`apps/api/src/index.js` 的 `isLocalDirect` / `requireLocal`）：

| 端点 | 为什么必须锁 |
| --- | --- |
| `POST /api/collect/trigger` | **原本完全无鉴权**。它能打 B 站接口、消耗 AI 审核额度、写缓存，被扫到就是白送一次全量采集 |
| `GET /api/progress/stream` | SSE 长连接，匿名可挂；每个连接都占着服务端资源 |
| `GET /api/progress/history` | 泄露采集历史与审核状态 |

**只查 `remoteAddress` 是挡不住的**：cloudflared 就跑在本机，它转发来的请求
`remoteAddress` 同样是 `127.0.0.1`。所以判据是三条同时成立：

1. `remoteAddress` 是环回；
2. **不带 Cloudflare 边缘头**（`cf-connecting-ip` / `cf-ray` / `cf-ipcountry`）——经隧道的请求一定有；
3. `Host` 去端口后是 `localhost` / `127.0.0.1` / `[::1]` —— 隧道请求的 Host 是隧道域名。

实测（2026-10-03）：隧道域名下三个端点全部 403（`collect/trigger` 的 GET 是 404，路由本就只收 POST）；
本机 `localhost:1003` / `127.0.0.1:1003` / `[::1]:1003` 全部 200；**伪造 `cf-ray` 或 `cf-connecting-ip` 也照样 403**。

##### 服务要脱离 DSH 的进程树

DSH 用 **Job 对象**管着它启动的所有子进程，DSH 一退出 Job 就关闭，里面的进程全被带走 ——
表现就是「不小心关掉 DSH，本地服务跟着一起没了」。`scripts/dev.js` 因此改用
WMI `Win32_Process.Create` 起服务：WMI 让 `WmiPrvSE.exe`（`services.exe` 的子进程）代它创建，
父链压根不在 DSH 树里。实测父链：

```
node.exe(服务) <- cmd.exe <- WmiPrvSE.exe <- svchost.exe <- services.exe <- wininit.exe
```

对照我自己：`powershell.exe <- DeepSeek Harness.exe <- ... <- explorer.exe`。
`start` 输出会明说 `已脱离 DSH 进程树（关掉 DSH 也不会被带走）`；失败则退回普通 `spawn` 并打印
`WMI 启动失败，退回普通 spawn` + `仍在 DSH 进程树内`，**不会假装成功**。

两个必须遵守的约束（都踩过）：

- **`CommandLine` 只用 ASCII，中文路径走 WMI 的 `CurrentDirectory` 属性**（那是属性不是命令行，
  不吃控制台代码页）。实测经命令行传中文，node 收到的是 `E:\缂栫▼\xngschina\...`。
  命令行里一律用相对 `svc.cwd` 的相对路径。本机 8.3 短路径**不可用**
  （`E:\编程\xngschina` 的 ShortPath 返回原样中文长路径）。
- **`stdio` 必须 `"ignore"`，结果走文件回传，不要读 stdout。** WMI 建出来的 `cmd.exe` 会继承
  PowerShell 的标准句柄，管道写端一直不关，父进程读 stdout 永远等不到 EOF ——
  实测 `spawnSync` 卡满 20s `ETIMEDOUT`、stdout/stderr 全空。
  现在由 PowerShell 把 `WMIOK <pid> <returnValue>` 写进 `.tmp/run/<name>.wmi.txt` 再读回。

> ⚠️ **别给这个 `powershell.exe` 调用加 `-ExecutionPolicy Bypass`。** 实测带 Bypass 时
> 4 次里卡死 3 次（12s / 23s / 12s 超时，只有 1 次 700ms 成功），去掉后 4/4 全 OK（约 700ms）。
> `-EncodedCommand` 走的是 base64 而不是 `.ps1` 文件，本来就不吃执行策略，加了纯属有害。

### 0.8 分页参数的坑：`Number(x) || 默认值`（已修复，留档）

2026-10-03 修掉的一类缺陷，记录在这里是因为**这个写法还会有人再写一遍**。

`Number(req.query.pn) || 1` 里 `0` 是假值，会被当成「没传」换成默认值。于是
`?pn=0` 变成第 1 页被放行，而代码自己写的 `pn < 1 → 400` 校验形同虚设——
**越界值被悄悄当成合法输入，比直接报错难查得多**。

统一改成 `index.js` 里的 `intParam(value, fallback)`：只负责区分「没传」和「传了」，
没传/空串给默认值，传了非数字返回 `NaN` 让范围校验去 400，传了则原样返回（含 0 和负数）。
已修四处：

| 位置 | 之前 | 现在 |
| --- | --- | --- |
| `/api/board/:kind` 的 `pn` / `ps` | `?pn=0`、`?ps=0` → 第 1 页 | 400 |
| `/api/search` 的 `page` | `?page=0` → 第 1 页 | 400 |
| `/api/owners` 的 `page` | `?page=0` → 第 1 页 | 400 |
| `/api/video/:aid/comments` 的 `page` / `page_size` | `?page=0` → 第 1 页 | 400 |

`?pn=`（空串）和不传参数都仍然走默认值 200，没有把老调用方打挂。

**没有一起改的**：`limit` / `ps` 那几处 `Number(x) || 10` 后面并没有声明要校验的意图，
`||` 在那里是刻意的容错默认值（`?limit=abc` 退化成 10 而不是报错）。改它们只会平白
多出一批 400，不属于修 bug。想统一风格的话请单独提一次，并且先确认前端行为。

## 一、布局对接：侧边栏按路由条件显示

### 1.1 参考站行为

- **带侧边栏的页面**（可通过左侧"快捷导航"进入）：左侧显示 `aside` 侧边栏 + 右侧内容；
- **不带侧边栏的页面**（视频详情、歌手详情、用户详情等）：无 `aside`，内容居中铺满。

### 1.2 侧边栏路由判定（前端唯一数据源）

文件：`apps/web/src/components/MobileNav.jsx`

```js
export const SIDEBAR_PREFIXES = [
  "/", "/rank", "/rank-block", "/search", "/singers",
  "/calculator", "/stats", "/achievements", "/today",
  "/interaction", "/ai", "/about", "/random", "/tags",
];

export function isSidebarRoute(pathname) {
  if (pathname === "/") return true;
  return SIDEBAR_PREFIXES.some(
    (p) => p !== "/" && (pathname === p || pathname.startsWith(`${p}/`)),
  );
}
```

判定规则：
- `/` → 带侧边栏；
- `pathname === prefix` 或以 `prefix + "/"` 开头 → 带侧边栏；
- 其余路径（如 `/video/:aid`、`/singer/:id`、`/member/:mid`、`/auth/success`）→ 不带侧边栏。

> 注意：`/singers`（歌手列表，含侧边栏）与 `/singer/:id`（歌手详情，不含侧边栏）是不同前缀。
>
> 注意：参考站**仅首页与榜单页**带 `<aside>`，本站 `SIDEBAR_PREFIXES` 覆盖更宽，
> 这是**按用户明确指定的规则**实现的，不要擅自按参考站收窄。

## 四、榜单增量口径（对接定义）

### 4.1 周期窗口

四类周期统一以**周期起始日 01:00** 为边界，实现在 `apps/api/src/services/index.js` → `windowOf()`：

| 周期 | 窗口 |
|---|---|
| 日榜 | 今日 01:00 ～ 明日 01:00 |
| 周榜 | 本周一 01:00 ～ 下周一 01:00 |
| 月榜 | 本月 1 日 01:00 ～ 下月 1 日 01:00 |
| 年榜 | 今年 1 月 1 日 01:00 ～ 次年 1 月 1 日 01:00 |

### 4.2 增量基线（重要）

增量 = 当前值 − **窗口起始日前一天**的快照值。

```js
// services/index.js
function baseDayKey(win) {
  return dayKeyOf(win.startTs - 86400);
}
```

- 快照按自然日归档于 `cache/stat_daily/YYYY-MM-DD.json`，而周期起点是 01:00，
  所以基线日必须写 `startTs - 86400`，**不能**写 `startTs - 1`
  （后者仍落在起始日当天，而当天快照会被当日采集反复覆盖，导致增量恒为 0）。
- 四类周期统一成立：日=昨天、周=上周日、月=上月末、年=上一年 12-31。
- 快照缺失时回退 evocalrank 周增量累加（`evoStats.sumWindow`），任意周期均适用。

### 4.3 新歌 vs 老歌

- **新歌**（`pubdate` 落在本窗口内）：无基线，用**当前累计值**计分；
- **老歌**：用上述增量计分。

### 4.4 历史回溯（上期排名 / 历史最高 / 成就）

`scoreWindow()` 用 `statHistory.deltaSnapshot(期初快照, 期末快照)` 还原历史某一期的分数，
口径与当期 `buildBoard()` 一致：

- 期初快照日 = `baseDayKey(win)`；期末快照日 = `dayKeyOf(win.endTs - 1)`；
- 首尾快照缺任一 → 返回 `null`，该期**跳过**（不当作「未上榜」）；
- 窗口内新歌无期初基线 → 用期末累计值；无基线且非新歌 → 该期无法还原，跳过。

据此派生的字段：`prev_rank` / `prev_score` / `delta`（相对上期分数增幅）/ `streak`（连续在榜期数）/
`peak_rank`（历史最高名次，仅优于当前时给出）/ `achievements`（见 4.5）。

### 4.5 永久成就

对齐 vocabili 的六类（旧四类 SUPERHIT / 门番达成 / 神话达成 / 年榜首位已于 2026-09-30 彻底下线）：

| 成就 | 条件 | 实现 |
|---|---|---|
| Emerging Hit! | 连续 3 期主榜前 5 | `best5 >= 3` |
| Mega Hit!!! | 连续 5 期主榜前 3 | `best3 >= 5` |
| 门番候补 | 15 期内有 10 期在前 20 | `ACH_COUNT_WINDOWS.potential_regular` |
| 门番 | 30 期内有 20 期在前 20 | `ACH_COUNT_WINDOWS.regular` |
| 日刊门番候补 | 15 期内有 10 期在前 20 | `ACH_COUNT_WINDOWS.daily_potential_regular` |
| 日刊门番 | 30 期内有 20 期在前 20 | `ACH_COUNT_WINDOWS.daily_regular` |

**类别归属榜单**（`ACH_BOARD_CATEGORIES`，对齐 vocabili 的 `board` 字段）：
周刊榜只产出前四类，日刊榜只产出后两类，月榜 / 年榜不产出成就。
不加这张表会让「日刊门番」出现在月榜/年榜上。

**窗口缩放**：官方窗口 `W0`/需要 `K0` 比例均为 2/3；站内可用期数 `N < W0` 时
窗口缩到 `N`、所需次数按比例缩放（`need = max(1, ceil(K0 * N / W0))`），
否则门番系在历史期数不足时永远为 0。描述文案仍展示官方口径。

**档案指纹缓存**：单个榜的档案可达 100MB（日刊 59 文件 / 100.9MB），
按类别重复扫描是这一块的主要开销（成就页 6 个面板 = 6 次全量读）。
`archiveFingerprint(board)` 只 `stat` 不读内容，档案增删改后自动失效；
`buildAllByBoard()` 一次扫描算出该榜全部类别并缓存，并发请求共享同一次构建。
实测：日刊首次 987ms → 命中缓存 10ms。

**跨榜混排（`board=all`）**：对齐 vocabili 首页「成就速递」——它调 `/achievement`
不传 `board`，一次拿到跨榜结果后本地排序取前 10。本站 `board=all&type=all`
遍历四榜合并，按 `achieved_date` 倒序。
**排序键必须用日期而非期号**：本站日刊期号已到 5900、周刊 843，两榜期号体系不同，
直接比期号无意义（原站 `lO()` 的基期换算不适用本站）。

回溯上限 `LOOKBACK_MAX = 50` 期；主榜定义为前 `MAIN_TOP = 20` 名。

### 4.6 数据依赖

历史回溯依赖 `cache/stat_daily/` 的每日快照密度。当前快照存在断档
（缺 08-20、08-21、08-29、09-07～09-11、09-18、09-19 等），
断档期会被跳过，故门番系成就的实际可判定期数少于理论值，属数据限制而非逻辑问题。

### 5.3.1 `xs:` 断点必须显式声明（否则全站 xs: 变体静默失效）

Tailwind **默认没有 `xs`**。原站用的是自定义 `xs = min-width: 400px`
（见其编译产物 `index-*.css` 的 `@media(min-width:400px){.xs\:...}`）。
本站 `apps/web/src/index.css` 的 `@theme` 里补了：

```css
--breakpoint-xs: 400px;
```

**没有这一行，全站所有 `xs:` 变体都不生效且没有任何报错**（榜单卡片、操作行、指标格全中招）。
另两档 `360px` / `460px` 在原站是任意值写法 `min-[360px]:` / `min-[460px]:`，不需要声明。

### 5.3.2 i18n 键必须**扁平**（`nsSeparator: "."` 的坑）

`apps/web/src/i18n/index.js` 的配置是 `nsSeparator: "."` + `keySeparator: false`。
后果：`t("calculator.bvFetcher.hint")` 会被切成 **命名空间 `bvFetcher` + 键 `hint`**，
而 `bvFetcher` 不是命名空间 → 直接把原始键渲染到页面上（表现为 `bvFetcherfalsehint`）。

**规则：`t()` 的第一个点号只用来分隔命名空间，键本身不能含点。**
嵌套要写成扁平键：

```js
// ✅ 正确
t("calculator.bvHint")          // calculator 命名空间下的 bvHint
t("calculatorDisplay.fixA")     // calculatorDisplay 命名空间下的 fixA
// ❌ 错误
t("calculator.bvFetcher.hint")
```

> 曾考虑改成 `nsSeparator: false`，但本仓库有多个 AI 并行改，动全局解析规则会波及所有命名空间，
> 因此选择「把新键拍平」这个零风险方案。

## 七、分数计算器（2026-09-26 新增）

### 7.1 官方评分公式模块 `apps/web/src/lib/officialScore.js`

从原站生产包 `index.js` 里**逐字逆向**出来的评分实现，是计算器页的唯一计分来源。
原站有三个变体 + 一个调度器：

| 原站函数 | 对应规则 | 本站导出 |
|---|---|---|
| `class v5` | `vocaloid-daily/weekly/monthly/annual/special/cover-weekly` | `computeScore(counts, { board })` 主路径 |
| `function x5` | `biliboard`（含 `timeOffset` 时间衰减） | 同上的 `biliboard` 分支 |
| `function w5` | `vc`（中文周刊） | 同上的 `vc` 分支 |
| `function S5` | `cat-weekly`（记录猫周榜） | 同上的 `cat-weekly` 分支 |
| `function xz` | 调度器 | `computeScore` 内的 board 分发 |

导出：`METRICS`、`BOARDS`、`COPYRIGHTS`、`hasFix(board)`、`needsIssue(board)`、
`NEW_WINDOW`（`7*86400`）、`fmt2`、`floorInt`、`computeScore`。

**七个必守口径（写错任何一个都会算出与原站不同的分）**

1. **全部用 `Math.ceil(x*100)/100`**（保留 2 位、向上取整），**不是 `toFixed`/`round`**；
2. **硬币为 0 但有播放+收藏+点赞时，硬币按 1 计**（`u===0 && o>0 && c>0 && f>0 → u=1`）；
3. **「自制」集合是 `[1, 3, 101]`**（1=自制、3=未定、101=转载投自制）→ `b=1`，否则 `b=2`；
4. **`fixTotal` 用「整数百分比」相乘**：`floor(round(fixB*100) * round(fixC*100) * round(fixE*100) / 1e4) / 100`，
   不是 `fixB*fixC*fixE`；
5. **`special` / `vocaloid-annual` 有后处理**：`fixB = ceil((fixB*.5+.5)*100)/100`，
   并重算 `fixTotal`；`viewR/2+.5`、`favoriteR/2+10`、`coinR/2+20`、`likeR/2+2.5`、`replyR/2+20`、`shareR/2+5`；
6. **`viewR` 分母 `×10` 只对 `vocaloid-daily` / `vocaloid-weekly`**，其余周期 `×15`；
7. 最终 `point = Math.round(fixTotal * 各项得分之和)`。

> 与后端 `apps/api/src/score.js` 的 `chartScore()` **是两套东西**：后端算榜单实际得分（走增量），
> 前端这套是按「累计值」复算给用户玩的，不要互相替换。

**等价性验证**：`old-files/debug/tmp-ui/verify-formula.js` 用括号深度匹配把原站 `v5/x5/w5/S5/xz/vz/k5/k1/en/Cf`
及两个 `Set` 从压缩包里抠出来，与本站实现跑随机 + 边界用例对拍 ——
**8 个 board × 5 个投稿类型 × 7 个 timeOffset，共 9612 例，0 处不符**。
（比较器要特判 `NaN`：两边除零都产生 `NaN`，`Object.is(NaN, NaN)` 为 `false` 会造成 865 个假阳性。）

### 7.5 与原站的两处有意偏离

1. **BV 取数不随每次按键重查**：原站 `useEffect(..., [input, tick])` 会在每次输入时都发请求；
   本站改成 `fetchRef` + 只在 `tick`（自动刷新/点「获取」）变化时触发。
2. **计算器不需要登录**：原站未登录时操作行第三格禁用、`/calculator` 页有登录门；
   本站计算器对所有人开放。
